## The task

The dataset is `names.txt`: 32,032 lowercase names, one per line (emma,
olivia, ava, isabella). The goal is a model that learns what names look like
and generates new ones. The dataset is small, but the concepts built here
carry to GPT without change: the loss, the sampling loop, and the evaluation
metric.

## What a language model is

A language model assigns probabilities to sequences. It factors the
probability of a sequence into one term per token:

$$P(\text{emma}) = P(\text{e at start}) \cdot P(\text{m}\mid\text{e}) \cdot P(\text{m}\mid\text{m}) \cdot P(\text{a}\mid\text{m}) \cdot P(\text{end}\mid\text{a})$$

Every deployed LLM is this same object: a machine that outputs
$P(\text{next token} \mid \text{context})$. GPT-4 conditions on thousands of
previous tokens. The model in this chapter conditions on one. That is the
only difference.

## The bigram model

The model works at character level. The token set has 27 entries: the 26
letters, plus one boundary token `.` that marks both the start and the end of
a name. The name "emma" gives the pairs `.e`, `em`, `mm`, `ma`, `a.`.

The whole model is a 27x27 table. Rows are the current character. Columns
are the next character. Each cell holds the count of that pair in the corpus.
Training is counting. To get probabilities, divide each row by its sum. Each
row then becomes a probability distribution over the next character.

Sampling is a walk through the table. Start at row `.`. Sample a next
character from that row's probabilities. Move to that character's row.
Repeat until `.` is drawn again.

Evaluation asks: on real data, how surprised was the model, on average? For
$N$ bigram occurrences, where the model gave probability $p_i$ to the $i$-th
occurrence:

$$\text{NLL} = -\frac{1}{N}\sum_{i=1}^{N} \log p_i$$

This is the average negative log-likelihood. A perfect model scores 0. The
score grows when the model assigns low probability to what actually occurs.
Perplexity is $e^{\text{NLL}}$. It reads as: the model is as uncertain as a
uniform choice among $k$ characters. A model that knows nothing has
perplexity 27.

## The exercise

Write the following, in a script or a notebook:

1. Load names.txt. Build the bigram pairs, with the `.` boundaries included.
2. Build the 27x27 count matrix. Map characters to indices 0 to 26.
3. Normalise the rows into a probability matrix.
4. Sample 10 names.
5. Compute the average NLL over the corpus, and the perplexity.

below 8 means a bug. One problem will appear in step 5: some bigrams never

you read on.

## What happened in the lesson

### The evaluation bug

N's first NLL computation, with `logP` the element-wise log of the
probability table and `N` the count matrix:

```python
NLL = -1 * logP.sum() / N.sum()     # gives 0.0155, absurd
```

An NLL of 0.0155 means perplexity 1.02: a model that predicts nearly every
character perfectly. The self-check caught it. The bug: `logP.sum()` adds
each of the 729 table cells once. It treats the never-seen `qz` and the
frequent `an` as equally important. The denominator counts all ~228,000
occurrences. The numerator lives in table space, the denominator in
occurrence space.

The fix is to weight each cell's log-probability by how often that bigram
occurs. That statement produced the sharpest challenge of the lesson:

> **N:** The formulae you gave earlier, none of them said this. Check before
> you contradict me.
>
> **Tutor:** The formulas and the weighting statement are the same thing. The
> index of the sum is where it hides. The sum runs over $i = 1 \ldots N$, the
> occurrences in the corpus. That is roughly 228,000 terms, duplicates
> included. Now regroup it. The pair `an` appears 5,438 times. Each of those
> terms is the identical number $\log P[a,n]$. Collect identical terms. The
> occurrence-space sum becomes a cell-space sum, and the counts appear as
> weights:
>
> $$\sum_{i=1}^{N} \log p_i = \sum_{\text{cells } (a,b)} \text{count}(a,b) \cdot \log P[a,b]$$
>
> The weighting was never an extra rule. It is what the original formula
> turns into when you change the summation index from occurrences to cells.

This distinction between occurrence space and cell space recurs throughout
the project. It reappears in the gradients of chapter 2. The two correct
implementations agree to ten decimal places:

```python
# occurrence space: one term per bigram in the data
total, n = 0.0, 0
for w in words:
    padded = "." + w + "."
    for c1, c2 in zip(padded, padded[1:]):
        total += logP[stoi[c1], stoi[c2]]
        n += 1
nll = -total / n

# cell space: counts as weights, one matrix expression
nll = -(N * logP).sum() / N.sum()
```

The loop is transparent and slow. The vectorised form runs in C. The skill
this project trains, more than any other: think in loops, compute in tensors.

### Smoothing, and what log(0) breaks

N anticipated the $\log 0$ trap and smoothed the counts before hitting it.
The implementation was more careful than the instruction: the denominator is
renormalised so rows still sum to exactly 1. This is Laplace smoothing, done
correctly:

```python
P = (N + 1) / (row_sums + 27)
```

The post-mortem exposed a subtlety. Asked why smoothing was needed:

> **N:** Division by zero was a mathematical problem without smoothening.
>
> **Tutor:** Close, but not the exact failure. Division by zero needs an
> all-zero row, and every row here has counts. The actual problem is
> $\log 0$. In the loop form on training data it never triggers, because you
> only look up bigrams that occur. In the vectorised form it does trigger:
> zero-count cells give $0 \times (-\infty)$, which NumPy evaluates to `nan`,
> and the sum is poisoned. On new data it is fatal: one unseen bigram makes
> an entire name's NLL infinite. Smoothing encodes a modelling stance:
> nothing is impossible, only unlikely.

GPT never faces this exact failure. Softmax outputs are strictly positive by
construction (chapter 2). The concern returns there in the form of
regularisation.

### Three ways to break a sampler

N's first generation loop contained three instructive bugs:

```python
ix = np.random.choice(np.arange(1, 27))       # bug 3
while curr_char != ".":
    curr_char = itos[np.argmax(P[ix])]        # bugs 1 and 2
    name += curr_char
```

1. `ix` never updates. The loop reads the same row forever. The sampled
   output must become the next input. That feedback is what autoregressive
   means. Without it there is no generation, only repetition.
2. `argmax` is not sampling. It picks the most probable next character,
   deterministically. All diversity collapses, and every generated name comes
   out identical. Greedy decoding against sampling is a real topic
   (temperature, chapter 9). Generation wants the weighted dice roll:
   `np.random.choice(27, p=P[ix])`.
3. The first character came from a uniform draw. The model already knows how
   names start. That is what the `.` row encodes. Start at `ix = 26` and the
   special case disappears. The boundary token exists so that "start of name"
   needs no separate code path.

The fixed loop, in full:

```python
total_names = []
while len(total_names) < 10:
    name = ""
    ix = 26                      # the '.' row: distribution over first letters
    curr_char = ''
    while curr_char != ".":
        ix = np.random.choice(27, p=P[ix])
        curr_char = itos[ix]
        name += curr_char
    total_names.append(name)
```

## Results

```
NLL        = 2.4546        (uniform model: ln 27 = 3.30)
perplexity = 11.64         (uniform model: 27)
```

Sampled names: `zllia`, `zala`, `ah`, `mietien`, `catysynan`, `cka`, `nalo`,
`ol`. Locally pronounceable, globally structureless. A one-character memory
works exactly this well and no better. This is the baseline every later
model must beat.

## What carries forward

- The model is $P(\text{next} \mid \text{context})$. Only the context grows
  from here.
- NLL is the loss. In chapter 2 it becomes the function gradient descent
  minimises. By chapter 8 the same formula is called cross-entropy loss.
- The autoregressive sampling loop survives verbatim to GPT.
- Occurrence space against cell space. Think in loops, compute in tensors.
