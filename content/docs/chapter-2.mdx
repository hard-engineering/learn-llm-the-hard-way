## Why counting does not scale

Chapter 1's model is a table with one row per possible context. That works
because a one-character context has only 27 possibilities. Two characters
need $27^2 = 729$ rows. Ten characters need $27^{10}$ rows, about 200
trillion, nearly all with zero examples. GPT conditions on thousands of
tokens. No table can hold that, and no dataset can fill it. The replacement
for the table needs a different procedure for setting its values, because
"count and normalise" only works for tables.

That procedure is this chapter. To learn it, we pick the one case where the
old and new roads can be compared: the bigram model itself. We rebuild the
exact 729-number model, set its values by the new procedure, and check that
it converges to the same answer counting gave.

The new procedure, in one paragraph. Start with 729 random numbers. Define a
single number that measures how bad they are as a model: chapter 1's NLL,
now viewed as a function of the parameters. For each parameter, work out
whether a small increase would raise or lower the loss. That is a
derivative. All 729 of them together form the gradient. Nudge each parameter
a small step downhill and repeat. This is gradient descent. It never
enumerates contexts. It works for any arrangement of numbers whose loss is
differentiable, and that is why the same procedure trains models with
trillions of parameters.

## The model, rebuilt

The 729 numbers live in a 27x27 matrix $W$, the same shape as chapter 1's
table. Two differences: it starts random, and its entries are arbitrary real
numbers ("weights"), not probabilities. Rows still mean current character.
Columns still mean next character.

Lookup becomes arithmetic. Encode the input character as a one-hot vector
$x$: 27 zeros with a single 1. Then $z = xW$ selects a row of $W$. Verify on
paper with a 3x3 example that one-hot times matrix equals row selection. The
27 numbers in $z$ are called logits: raw scores, unnormalised, possibly
negative.

Softmax converts scores to probabilities. Exponentiate, so everything is
positive. Then normalise, so the row sums to 1:

$$p_k = \frac{e^{z_k}}{\sum_{j=1}^{27} e^{z_j}}$$

Chapter 1 normalised positive counts by their row sum. Softmax is the same
move, applied to exponentiated scores, so it works on any real numbers. One
side effect: softmax outputs are strictly positive, so the $\log 0$ problem
of chapter 1 cannot occur here.

The loss is chapter 1's NLL, with $p$ now coming from $W$ instead of from
counts. For one example with correct next character $y$, the loss is
$L = -\log p_y$. Averaged over all ~228k bigrams, this is the function
gradient descent will minimise. A random $W$ scores about 3.3, the level of
uniform guessing. The counting model's 2.45 is the target.

## The derivation, on paper

Everything depends on one gradient: how does the loss change as each logit
moves? The required calculus: the derivative of $\log x$ is $1/x$, the
derivative of $e^x$ is $e^x$, and the chain rule. One bookkeeping fact: while
differentiating with respect to $z_k$, every other $z_j$ is a constant.

**Step 1. Simplify before differentiating.** With $S = \sum_j e^{z_j}$:

$$L = -\log\frac{e^{z_y}}{S} = -z_y + \log S$$

**Step 2. First term.** The derivative of $-z_y$ with respect to $z_k$ is
$-1$ when $k = y$, else $0$. Compactly: $-\mathbb{1}[k=y]$, where
$\mathbb{1}$ is 1 when the condition holds and 0 otherwise.

**Step 3. Second term.** Apply the chain rule to $\log S$. In the sum $S$,
only the term $e^{z_k}$ depends on $z_k$:

$$\frac{\partial \log S}{\partial z_k} = \frac{1}{S} \cdot e^{z_k} = p_k$$

The derivative of log-sum-exp is the softmax. That is not a coincidence. It
is why this pairing of functions exists.

**Step 4. Combine.**

$$\frac{\partial L}{\partial z_k} = p_k - \mathbb{1}[k=y]$$

As a vector over all 27 logits at once: gradient = $p - \text{onehot}(y)$.
Predictions minus truth.

Read it as instructions. For a wrong character $k$, the gradient is $p_k$,
positive, so that logit gets pushed down, in proportion to the probability it
wrongly claimed. For the correct character, the gradient is $p_y - 1$,
negative, so it gets pushed up, in proportion to what it failed to claim. A
perfect prediction gives an all-zero gradient. Learning stops by itself.

One hop remains. Since $z = xW$ with $x$ one-hot at position $i$, each
$z_k$ is literally $W[i,k]$. So the vector $p - \text{onehot}(y)$ is the
gradient of row $i$ of $W$, and all other rows get zero from this example.
Chapter 1's counting touched one row per bigram and incremented one cell.
Gradient descent touches the same row and adjusts all 27 entries in it.

## The exercise

1. Build integer arrays `xs`, `ys`: about 228k input/target index pairs.
2. Initialise `W = np.random.randn(27, 27)`.
3. Forward pass: `logits = X @ W` (or `W[xs]`), softmax the rows, then
   `loss = -np.log(probs[np.arange(n), ys]).mean()`.
4. Backward pass: `dlogits = probs.copy()`, subtract 1 at the target
   columns, divide by `n`, then `dW = X.T @ dlogits`.
5. Update: `W -= 50 * dW`. Loop 200 times. Print the loss every few
   iterations.

Success: the loss starts near 3.3 and descends toward 2.45. Then softmax the
trained $W$'s rows and run chapter 1's sampler on the result, unchanged.

## What happened in the lesson

### "Shouldn't each character's gradient be averaged over its own examples?"

The instruction `dlogits /= n`, divide by the total number of examples, drew
the sharpest question of the lesson:

> **N:** Shouldn't the dlogits accumulate for char $i$ and then take the mean
> over the number of training examples of $i$?
>
> **Tutor:** Look at what we are taking the gradient of. The loss was defined
> as the mean over all $n$ examples, and differentiation is linear:
>
> $$\frac{\partial L}{\partial W} = \frac{1}{n}\sum_{i=1}^{n} \frac{\partial L_i}{\partial W}$$
>
> That is the sum of per-example gradients scaled by $1/n$, no matter which
> row each lands on. Your proposal is the gradient of a different loss, one
> where every context is weighted equally regardless of frequency. Our loss
> lives in occurrence space. Frequent contexts contribute more terms, so
> their rows receive proportionally larger pushes. That is not a bug to
> normalise away. It is the model allocating learning effort by how often
> each context matters. It would be strange for one `qz` sighting to move
> the model as forcefully as ten thousand `an`s.

Chapter 1's occurrence-space against cell-space distinction, reappearing in
gradients.

### The 27x27 collapse

> **N:** The computation of $p$ of a row is unaffected by $n$. Can we not
> keep it computed for $W$, which is 27x27, instead of $xW$, which is
> $n$x27?

Yes, and noticing this is noticing something real. With only 27 distinct
inputs, the $n$x27 `probs` matrix holds at most 27 distinct rows. The whole
computation collapses into cell space, everything 27x27, cheaper by a factor
of about 8,000. Better still, set the collapsed gradient to zero and solve:

$$p_i = N[i,:] / c_i$$

Softmax of the optimal $W$ equals the count-normalised table of chapter 1.
This is the promised equivalence, as algebra rather than as an empirical
convergence claim. Gradient descent's destination is exactly what counting
computes directly.

Why practice the $n$x27 form anyway: the collapse exists only because
examples with identical inputs are identical computations. That dies in
chapter 3. Embeddings and a hidden nonlinearity make every example's
computation distinct. From there on, a matrix with one row per example (a
batch) is the universal shape.

### Reading the training curve

The final loop (see notebook) produced:

```
0   3.6147
25  2.5432
50  2.4970
100 2.4734
195 2.4630
```

Three observations in these numbers.

- The loss starts at 3.61, not 3.30. A random Gaussian $W$ is not ignorant.
  It has opinions, random ones, confidently wrong in random directions. The
  noise costs about 0.3 nats over honest ignorance. An all-zero $W$ would
  start at $\ln 27 = 3.2958$ exactly. This foreshadows chapter 8:
  initialisation is chosen so that networks start life uniform, not
  opinionated.
- The curve flattens because the gradient is $p - \text{onehot}(y)$, and it
  shrinks as predictions approach observed frequencies. The descent is
  asymptotic, not stuck. It crawls toward counting's 2.4546 and never quite
  arrives.
- The destination is the counting table. Verify it directly: softmax the
  trained $W$'s rows and compare against chapter 1's $P$ matrix entry by
  entry.

### Incidental lessons from the notebook

- `probs[np.arange(n), ys]` is paired fancy indexing. Two equal-length index
  arrays walk in lockstep and return element $(i, y_i)$ for every $i$. Not
  all combinations; that would be slicing. The same idiom implements the
  one-hot subtraction: `dlogits[np.arange(n), ys] -= 1`.
- One-hots are mostly avoidable. `W[xs]` does the forward lookup, and
  fancy-indexed subtraction does the backward one. The single genuine use is
  `X.T @ dlogits`. Even that has a scatter-add alternative,
  `np.add.at(dW, xs, dlogits)`. Do not write `dW[xs] += dlogits`: it
  silently drops duplicate indices, a classic NumPy trap.
- A `while` loop with a counter that never increments runs forever. Use
  `for i in range(200)` for counted loops. Reserve `while` for stopping
  conditions that are states, like the sampler's "until `.` is drawn".
- The learning rate was 50, large by deep-learning standards. It is
  tolerable here because dividing the loss by $n$ makes per-parameter
  gradients small, and this near-convex problem has no cliffs. Why the loss
  is a mean and not a sum: it decouples gradient magnitude from dataset
  size, so the learning rate is a property of the model, not of the data
  volume.

## What carries forward

- $\nabla_z L = p - \text{onehot}(y)$: the gradient that starts
  backpropagation in every model from here to GPT, with 50,000 logits
  instead of 27.
- Softmax normalises a row of scores. Logits are pre-probability scores.
- The batch shape: one row per example, all examples computed at once.
- Counting and gradient descent agree where both exist. Only gradient
  descent survives what comes next.
